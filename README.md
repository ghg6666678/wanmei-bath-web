# 智水 · 网页版（Python）

完美校园「智慧用水 → 洗澡」的精简网页客户端：只保留预约、取消预约、限时限额、用水记录，去掉开屏广告和首页。

手机浏览器打开即可用，也可以「添加到主屏幕」当 App 使用。

> **关于本项目**：这是一个 AI coding 项目。作者此前没有相关开发经验，从界面、协议到构建、审计与文档，全程都是通过与 AI agent 用自然语言交流完成的。

## 依赖

- Python 3.9+
- 依赖包：`pip install -r requirements.txt`（requests、pycryptodome）

不需要 Node.js，签名已经用 Python 实现。

## 快速开始

```bash
pip install -r requirements.txt

python login.py        # 手机号 + 短信验证码登录，票据写入 config.json
python server.py 8770  # 启动服务
```

也可以不跑 `login.py`：直接打开网页，用手机号 + 短信验证码登录（票据同样写入 `config.json`）。

Windows 上也可以直接双击 `启动.bat`（会调用 `server.py`）。

启动后终端会打印局域网地址，例如 `http://192.168.1.20:8770`，**手机连同一个 WiFi** 用浏览器打开即可。

## 在线部署（WorkBuddy Sites / 任意单端口容器）

想让手机在校外也能打开，不必和电脑连同一个 WiFi，可以发成带分享码的外链。但**必须开无状态模式**：票据加密后放在浏览器 cookie，服务端不保存任何账号数据（见 `docs/STATELESS.md`）。**绝对不要用默认的「单人自用」模式对外服务**——那会把登录态写在服务端，换个人登录就互相覆盖。

容器会注入 `PORT` 环境变量，`server.py` 优先读它；本地仍支持 `python server.py 8770`。启动命令示例：

```bash
BATH_STATELESS=1 BATH_COOKIE_SECURE=1 python3 server.py
```

`BATH_COOKIE_SECURE=1` 在 HTTPS 下给 cookie 加 `Secure`。不设 `BATH_STATE_KEY` 时会在运行目录生成 `state.key`，删掉它等于让所有人重新登录一次；固定密钥请用 64 位十六进制的环境变量，别写进仓库。

**注意事项**：

- 分享链接带分享码，不带码访问会 403；**只发给本人或信任的人**，不要发到公开群。
- 这个服务会向校园水控接口转发请求（含发送短信验证码），任何拿到链接的人都能触发。别公开扩散。
- 云端不下发任何账号信息；不要把 `config.json`、`state.key` 或真实票据放进部署目录。
- 不想用了可在「设置—数据管理—发布的应用」里下线，链接立即失效。

> 关于「为什么不做服务全校的在线版」，见文末。带分享码、只给本人或少数人的**受限外链**不属于那种形态，但「出口集中」的风险仍然在，规模一大就该收回。

## 目录结构

```
server.py       HTTP 服务（静态页 + JSON 接口 + 网页登录/退出 + 版本检查）
statebox.py     无状态会话：票据加密进 cookie，服务端不保存（多人部署时启用）
vwater.py       智慧用水业务的协议实现（会话、预约、记录、限时限额）
wxlogin.py      登录流程实现（建立会话、参数加密、签名）
updater.py      检查更新：多通道探测 GitHub，本地清单 / 缓存兜底
login.py        登录命令行：拿 session 并写入 config.json
web/index.html  单页界面
web/latest.json 版本清单（GitHub 读不到时的兜底，发版时更新）
config.json     登录后生成，含票据和个人信息（已在 .gitignore 中）
docs/STATELESS.md  无状态会话的实现说明与移植指南
CONTRIBUTING.md 贡献说明
```

## 它是怎么工作的

1. `login.py` 先建立会话：客户端生成一对临时密钥交给服务端，换回会话标识与一份密钥材料
2. 用**同一个会话**提交短信验证码登录，服务端把它升格为账号会话
3. 这个会话就是「智慧用水」要的凭据；网页端登录走 `/api/native`，复用同一套 `WxLogin` 会话（发码与登录必须是同一个会话）
4. 之后每次业务请求都要带会话标识、当前时间，以及由这两者算出的签名

签名规则与常量不在 README 展开，实现见 `vwater.py`。所有协议都用 Python 标准库加 `pycryptodome` 实现，不需要 Node.js。

## 功能

- 余额、当前预约（验证码三行居中大字号 + 当日有效倒计时）
- **星标宿舍楼**：只显示自己那栋楼，同楼 A/B 区合并（某个区设备坏了可去另一区）
- 一键预约 / 取消预约
- 消费限时、限额：滑块 + 文本框联动，金额以 **0.05 元**为步进（与浴室实际扣费单位一致），服务端按「分」做整数校验
- **保存限额后自动取消所有已有预约**：订单里存的是预约当时的数值，不重新预约不生效
- 顶部下拉刷新；所有弹窗按住顶部横条下拉可跟手关闭
- **检查更新**：服务端代查 GitHub（官方接口 → CDN 清单 → 本地清单 → 缓存），GitHub 打不开时仍给出 Android 客户端的最新版本、下载地址与 SHA-256；网页端本身刷新即最新
- 首页「充值」按钮弹出说明弹层；退出登录有二次确认；登录失效先提示再自动弹登录框
- 最近 6 个月的用水记录
- 深色模式自适应、可「添加到主屏幕」（PWA）

## 已知限制

- **单点登录**：在这里登录会让手机上的原版 App 下线（错误码 `100600`），反之亦然
- **充值只给指引**：点首页「充值」会弹出说明，指引到微信小程序「完美校园」充值。原版支付校验 `appid + 包名 + 签名` 三者绑定，第三方客户端调不起，本工具不处理支付
- 会话会过期；失效时会自动提示并弹出登录框，在网页里重新登录即可（也可以重跑 `python login.py`）
- **默认模式只在可信局域网使用**：票据写进 `config.json`，进程里只有一份会话，换人登录会互相覆盖。**这个模式不要暴露到公网**；要对外访问请开无状态模式，见「在线部署」

### 为什么不做「一个服务器服务全校」的网页版

除了上面那条许可边界，还有个更实际的原因：**一个出口承载所有人，流量特征太集中，风控最先盯的就是这种。**

同类项目里已经有过教训——把反代服务器架起来给全校网页版用户共用，结果被教务系统按 IP 限流，一挂全挂。

而这个 App 的形态恰好相反：**每个人用自己的网络、自己的 IP、自己的登录态**，流量天然分散，跟一个真人反复打开官方 H5 没有区别。这不是刻意规避风控，是「单机工具」这个定位自带的性质。

所以如果有人想把它改成「注册即用」的在线服务，技术上要先解决会话隔离，架构上要面对出口集中，两关都不好过——**这条路不建议走**。

「在线部署」一节里的带分享码外链，是**给自己或少数信任的人**用的受限入口，不是面向全校的公共服务；分享码本身就是访问控制。但出口集中的风险不会因此消失，一旦链接扩散、使用人数上去，就该及时收回。

本仓库不含任何真实账号数据；`config.json` 是本地生成的文件，不会被提交。
