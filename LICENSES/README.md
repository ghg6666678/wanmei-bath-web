# 单独授权记录

`LICENSE` 里提到的那种「另行授予」的许可，记在这里。每条一个文件，命名 `<项目名>.md`。

每个文件至少写清三件事：

- **授权对象**：哪个项目、谁维护、仓库地址
- **授权范围**：允许做什么，明确排除什么
- **时间与形式**：什么时候、通过什么方式（Issue 答复 / 邮件）确认的

单独授权只对该项目有效，不自动扩展到它的衍生版本，也不改变 `LICENSE` 对其他人的效力。

## 这些情况不用来问

`LICENSE` 已经明确允许，直接做就行，不需要申请、也不需要登记：

| 情形 | 依据 |
| --- | --- |
| 手机 App 直接连，用户在自己设备上登录自己的账号 | 允许第 2、5 条 |
| 网页 + 反代，只要不落盘、不写进日志、不跨用户共享、一次请求一个会话 | 允许第 7 条 |
| 做给同学用的小工具 | 允许第 5 条 |
| **自己改外观、主题色、文案等主观偏好，留着自己用** | 允许第 3 条 |
| **fork 本仓库、为提交 PR 创建分支** | 允许第 4 条 |
| **在自己的工具/网站里放一个友情链接指向本项目（或反过来互推）** | 允许第 6 条 |
| 引用代码、写文章、做教学，注明出处 | 允许第 8 条 |

其中「网页 + 反代」这条特意写清楚：**浏览器要跨域就得有服务器转发，而 iOS 用户没有客户端可选，只剩网页**。转发不是代登录，不该被同一条款误伤。

「友情链接」这条也是认真的：这类校园工具本来就该互相带路，一个不带任何对价的链接既不是收费也不是广告。

## 这些需要来问

- 把付费变成使用门槛（不付钱用不了部分或全部功能、打赏解锁、会员专享等）
- 插入严重影响使用体验的广告（开屏、插屏、跳不过、切回重播等）
  > 纯自愿、无对价、不影响功能的赞赏入口**不在此列**，见 `LICENSE` 允许章节的说明。
- 公开发布安装包、上架应用商店，或公开发布含本项目修改后源码的仓库
- 服务端**持有**票据、多账号池、批量操作
